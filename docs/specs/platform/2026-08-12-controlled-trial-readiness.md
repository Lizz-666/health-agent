# Phase 9 Android 小范围受控试用候选版规格

> 日期：2026-08-12
> 状态：Gate 0 决策已收敛，等待 exact-SHA 验证
> 唯一业务基线：`2ae03345a93d8cc22d0e47fcac415411798df48b`
> 基线分支：`codex/phase8-flutter-driver`

## 1. Outcome

把 Phase 8 已验证的“合成数据 Android 个人开发版”推进为一个可供后续小范围、
非公开受控试用评估的 Android 候选版。Phase 9 建立生产意图的身份边界、隐私与
安全证据、中文化、可访问性、设备与网络可靠性、监控和事故响应准备，但 Gate 0-4
仍只处理合成数据。

Phase 9 Gate 4 的最高结论是 `controlled-trial candidate`，不是部署、真实用户试用、
公开发布、法律合规批准、健康专业批准或安全认证。

## 2. 已批准范围

### 2.1 地区、受众、渠道与责任

- 目标地区：中国大陆。
- 目标受众：一般健康成年人；不面向未成年人、受限人群或医疗用途。
- 候选渠道：Android 非公开分发候选，不进入公开应用商店，不提供公众下载入口。
- 运营责任：项目所有者是候选阶段的产品与运营责任人；支持和事故联系人必须在
  真正试用前以可用联系方式登记。
- 产品定位：健康科普、普通体态筛查辅助、一般健身与饮食执行支持；不提供诊断、
  治疗、专业康复、疾病营养治疗或紧急服务。

### 2.2 数据、AI 与照片边界

- Gate 0-4 的开发、测试、评测、日志、截图和 CI 始终只使用合成数据。
- 不使用真实健康档案、症状、饮食限制、照片、手机号、邮箱或真实测试者凭据。
- live AI、真实照片分析和云端照片上传保持关闭。
- 不接入生产短信、邮件、模型、对象存储、监控或其他付费提供者。
- 不部署、不写 `main`、不 merge、不公开发布；任何外部写入仍按仓库授权单独处理。

### 2.3 受控试用身份方案

采用“唯一邀请码 + 每名测试者独立的单机内测账号”作为候选身份模型：

1. 每个邀请码只能激活一个预配置的独立测试账号；邀请码不可复用、可过期、可撤销。
2. 邀请码仅决定注册/激活资格，不替代持续登录凭据、用户身份或 API 授权。
3. 每名测试者拥有独立内部用户 ID 和凭据，不允许共享万能账号或静态通用密码。
4. 候选阶段凭据线下发放，不建立自助注册、公众找回或短信/邮件发送能力。
5. “单机”表示一个账号只允许一个已登记试用设备/活动设备绑定；换机或恢复由运营者
   人工撤销旧绑定后处理。设备标识不得使用不可撤销的硬件指纹。
6. 认证提供者置于接口边界之后。未来短信验证码替换的是凭据验证/找回方式，不改变
   内部用户 ID、邀请码资格、会话、授权、数据所有权或删除契约。

详细架构决定见 `docs/adr/0009-invited-trial-authentication-boundary.md`。

## 3. Non-Goals

- 不开始真实用户招募或真实健康数据试用。
- 不购买或启用短信、邮件、托管数据库、云监控、对象存储或模型服务。
- 不完成应用商店上架、备案、商业条款、支付、容量扩展或公开支持体系。
- 不把 Codex 内部审查描述为律师法律意见、执业健康专业意见、独立渗透测试或认证。
- 不启用 live AI、真实照片、摄像头/相册权限或照片存储。
- 不承诺完整离线业务、iOS、可穿戴设备或多端同时登录。

## 4. 审查与授权分层

### 4.1 Codex 可完成的内部审查

Codex 负责并可签署项目内部工程结论：

- 规格、架构、真实 diff、鉴权和授权边界审查；
- 威胁模型、依赖供应链、secret 管理、日志脱敏和失败路径审查；
- 隐私数据清单、数据流、保存/删除/备份设计与合成数据验证；
- 健康产品边界、确定性安全策略与当前权威一手来源的一致性预审；
- 中文化、可访问性、Android 设备/网络/时区/升级回滚验证；
- exact-SHA 本地和 GitHub CI 证据、Gate 审查和退出审计。

### 4.2 Codex 不能替代的外部审查

用户当前没有相关专业人员渠道，决定 Phase 9 不产生外部审查费用。以下项目保持
`not obtained`，且不能由 Codex、OpenCode 或绿色 CI 豁免：

- 合格律师或隐私专业人员针对实际运营主体、地区、数据流和发布方式的法律意见；
- 合适的运动医学、康复、健身或营养专业人员对健康主张、红旗和升级文案的独立意见；
- 独立安全人员或机构针对真实部署面的渗透测试或安全认证。

缺少这些独立审查不会阻止 Phase 9 内部候选版工程工作，但会阻止真实健康数据试用、
面向外部测试者的正式启动和公开发布。真正试用前，用户可以另行决定取得外部意见，
或明确接受只允许更窄、无真实健康数据的演示范围；Codex 不替用户接受该风险。

## 5. 身份与授权契约

### 5.1 稳定领域身份

- `user_id` 是稳定、非手机号/邮箱的内部主体标识。
- 邀请记录、账号、设备绑定、会话和数据所有权是独立对象。
- API 授权始终从服务端已验证会话取得主体，不信任客户端传入的用户 ID。
- 用户数据读写、导出和删除继续按主体隔离；邀请状态不能扩大数据权限。

### 5.2 Provider 端口

认证应用层使用窄接口表达：

- 凭据验证；
- 账号恢复资格；
- 提供者健康/不可用状态；
- 审计所需的脱敏提供者结果。

本地候选实现可以验证预配置账号凭据；未来短信 provider 可以验证一次性验证码。
领域层不得依赖短信供应商 SDK、手机号格式或发送回执。

### 5.3 Fail-Closed 要求

- 非候选配置下发现默认/弱 JWT secret、开发登录、合成凭据或缺失关键配置时拒绝启动。
- 邀请码未知、已用、过期、撤销、账号不匹配或并发重复消费时不得激活账号。
- 账号禁用、设备绑定冲突、token 撤销、过期或签名错误时拒绝访问。
- 登录、邀请码和恢复接口必须有限速、失败审计和不泄露账号是否存在的响应。
- 日志不得记录邀请码、密码、验证码、完整 token、真实联系方式或健康正文。
- provider 不可用不能降级到开发账号或绕过认证。

## 6. 隐私、同意与数据生命周期

Phase 9 必须形成并验证以下候选证据：

- 数据清单与数据流图：身份、邀请、设备、健康档案、计划、签到、体重、Agent 上下文、
  饮食、照片关闭路径、日志、监控、导出、删除和备份。
- 每项数据的目的、必要性、来源、存储位置、访问者、保存期限、删除语义和第三方处理者。
- 健康敏感个人信息的独立告知/单独同意设计、撤回和版本化证据；合成测试验证行为。
- 账号删除对所有用户拥有域、对象、审计最小保留项和备份到期删除的明确语义。
- 备份恢复不能使已删除账号恢复为可用状态；恢复后必须重放删除墓碑或等价机制。
- 日志、崩溃报告和监控默认只记录稳定错误码、请求相关 ID 和聚合指标，不记录健康正文。

这些设计不授权收集真实数据。真实试用前还需要绑定实际运营主体、处理地点、供应商、
保存期限和用户可访问文本，并完成适用的个人信息保护影响评估。

## 7. 安全、供应链与运维

### 7.1 威胁模型最低范围

- 邀请码猜测、重放、并发消费和批量枚举；
- 凭据填充、暴力破解、共享账号和设备绑定绕过；
- JWT secret 泄漏、token 重放、会话撤销失败和越权访问；
- Android 包被转发、客户端配置篡改、明文流量和错误环境连接；
- API 枚举、IDOR、批量抓取、日志泄露和错误详情泄露；
- 依赖投毒、未固定 CI Action、构建产物混入 secret；
- 删除不完整、备份恢复复活、监控失效和事故响应延迟。

### 7.2 运维证据

- 候选环境配置清单、secret 生命周期与轮换/撤销步骤；
- 最小权限、健康检查、结构化脱敏日志和关键安全指标；
- 登录失败、邀请异常、5xx、删除失败和服务不可用告警设计；
- P0-P3 事故分级、联系人、止损、通知、证据保全、恢复和复盘 runbook；
- APK、后端和数据库版本兼容矩阵，升级、回滚和数据恢复演练；
- 已知漏洞接收、依赖更新、紧急禁用账号/邀请/版本的流程。

## 8. 中文化与可访问性

- 用户可见核心流程不得暴露英文知识源步骤、机器枚举、内部 ID 或原始服务错误。
- 安全关键未知值 fail closed，并显示稳定中文说明；普通未知显示字段使用审查过的中文兜底。
- 关键交互具备可理解的 Semantics 标签、角色、状态和操作提示。
- 文字放大到至少 200% 时，核心登录、档案、计划、Today、Agent、饮食和周复盘流程
  不截断关键内容、不遮挡操作、不依赖横向滚动完成任务。
- 关键文字/控件进行对比度检查；颜色不是状态的唯一表达。
- TalkBack 顺序、焦点、错误播报、按钮命名和动态状态更新通过目标设备验证。

## 9. 设备、网络、时区与升级回滚

- 目标 Android 版本和设备矩阵在 Gate 3 冻结；至少覆盖当前 API 34 基线和一个较低受支持版本。
- 验证冷启动、后台恢复、token 过期、服务不可达、慢网、断网重试和重复提交。
- 服务端统一使用 UTC 持久化，用户日界按 `Asia/Shanghai` 解释；跨午夜、周界和 token
  过期必须有合成测试。
- 客户端/服务端版本不兼容时明确阻断，不产生半写入状态。
- 升级与回滚不得破坏邀请、账号、设备绑定、同意、用户数据和删除墓碑。

## 10. Gate 0-4

| Gate | 结果 | 写入者 | 硬门 |
| --- | --- | --- | --- |
| Gate 0 | 决策、规格、ADR、计划和阻断项冻结 | Codex | exact Phase 8 base；文档一致；无 P0/P1/P2；exact-SHA CI |
| Gate 1 | 受控试用身份与生产配置边界 | Codex | 邀请/账号/设备/会话 fail closed；开发认证不可进入候选配置 |
| Gate 2 | 隐私、安全、供应链和运维证据 | Codex | 数据流/删除/备份/威胁模型/事故 runbook；仅合成数据 |
| Gate 3 | 中文化、可访问性和 Android 可靠性 | 一个 OpenCode Flutter 批次，随后 Codex 接管审查 | 冻结 allowlist；TalkBack/200%/网络/时区/升级回滚证据 |
| Gate 4 | 集成候选版退出审计 | Codex | Full + Flutter + synthetic E2E + Android + exact-SHA CI；无 P0/P1/P2 |

每个 Gate 的 CI 只证明该 SHA 上自动化验证通过，不构成真实试用、部署或发布批准。

## 11. Acceptance Criteria

Phase 9 Gate 4 只有满足以下条件才可标记 `controlled-trial candidate`：

1. 所有实现都可追溯到唯一基线 `2ae03345a93d8cc22d0e47fcac415411798df48b`。
2. 唯一邀请码、独立账号、单活动设备、会话撤销和用户数据隔离通过合成验证。
3. 候选配置不能启用开发登录、默认 secret、共享账号、live AI 或照片路径。
4. 隐私数据流、同意、导出、删除、备份到期和日志脱敏有设计与合成证据。
5. 威胁模型、依赖/CI 供应链审计、监控指标和事故响应演练记录齐全。
6. 核心用户流程完成中文化、200% 大字、TalkBack 和关键对比度检查。
7. 目标 Android/网络/时区/升级回滚矩阵通过，无错误成功态或半生效状态。
8. 本地完整验证、Phase 9 synthetic E2E、Android 回放和同一 exact SHA 的 GitHub CI 通过。
9. Codex findings-first 冷审无未解决 P0/P1/P2；P3 和未完成的外部审查明确记录。
10. 退出报告明确声明未使用真实数据/照片/联系方式/生产凭据/live provider，未部署或发布。

## 12. Rollout 与进一步授权

Gate 4 后仍需单独的用户决定和授权才能进入真实试用，包括：

- 确定真实测试者、运营/支持/事故联系人和分发方式；
- 决定是否处理真实健康数据，并批准对应隐私文本、同意和影响评估；
- 决定是否取得法律/隐私、健康专业和独立安全审查；
- 批准托管、短信/邮件、监控等外部供应商、凭据和成本；
- 批准部署、分发和真实用户数据处理。

公开发布继续完全受 `docs/product/public-release-gate.md` 约束。
