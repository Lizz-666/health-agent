# 健康教练 Agent 安全边界

> 日期：2026-06-12
> 适用阶段：个人开发验证

## 1. 基本边界

产品提供健康科普、体态筛查辅助、普通健身计划、普通饮食建议和执行管理。

产品不得：

- 将自测或照片结果表述为医学确诊
- 宣称替代医生、物理治疗师、营养师或专业教练
- 承诺纠正畸形、治疗疾病或保证效果
- 仅依赖结尾免责声明放行高风险建议
- 在 AI 失败时返回“正常”或其他看似安全的假结果

## 2. 风险分级

| 等级 | 典型情况 | 产品行为 |
| --- | --- | --- |
| 普通 | 无明显限制的普通成年人 | 可生成完整范围内的计划 |
| 谨慎 | 新手、信息不足、既往疼痛、恢复较差 | 保守计划，增加追问和限制 |
| 受限 | 孕期、术后、重大慢性病、明显伤病、饮食障碍风险等 | 允许问答和体态辅助；计划采用受限策略，必要时要求专业确认 |
| 红旗 | 急性创伤、明显神经或心血管等风险信号 | 停止相关计划生成或执行，提供及时就诊建议 |

所有用户拥有产品访问权，但推荐强度和可执行动作根据风险等级变化。

风险规则必须由版本化代码或策略数据实现，不能只写在 Prompt 中。

## 3. 体态安全

- 体态结果记录为“筛查信号”或“评估结果”
- 明确展示评估方式、时间、范围和不确定性
- 自测与照片分析冲突时保留冲突状态
- 关联图谱只能用于推荐排查和解释，不得直接认定病因
- 新发严重疼痛、麻木、无力、眩晕、急性创伤等配置为停止条件
- 图示需要展示安全姿势、常见错误和停止条件

## 4. 训练安全

计划生成前必须具备：

- 用户选择的体态评估结果
- 健身目标
- 每周频率和单次时间
- 徒手或弹力带条件
- 疼痛、伤病和限制信息
- 当前风险等级

动作库必须结构化记录：

- 适用目标和体态问题
- 难度、目标肌群、动作模式
- 所需器械
- 禁忌和停止条件
- 简化、进阶和替代动作
- 训练量和进阶规则

安全规则先过滤动作和负荷，AI 只能在允许范围内组合与解释。

## 5. 饮食安全

- 只支持普通饮食建议
- 即使不支持特殊饮食，也必须记录并排除过敏和明确忌口
- 营养目标和份量换算由确定性计算与食物数据库完成
- AI 不得自行发明营养值、过敏信息或疾病饮食限制
- 用户界面展示估算区间，不制造无法由份量估算支持的精确数值
- 疾病治疗饮食、孕期、未成年人和饮食障碍风险进入受限策略

## 6. Agent 工具安全

每个 Tool 必须具备：

- 明确、类型化的输入输出
- 当前用户授权检查
- 最小必要数据读取
- 明确副作用
- 可重试或幂等策略
- 失败状态和审计记录

Agent 不直接执行任意 SQL，也不将自然语言直接写入正式档案或计划。

长期结构变化需要用户确认。当日小调整可以自动执行，但必须记录调整原因并向用户展示。

## 7. 数据和隐私

体态照片、身体数据、疼痛、疾病、饮食限制和健康档案按敏感数据处理。

个人开发阶段也应做到：

- 最小化采集
- 区分用户陈述、测量数据、算法计算和 AI 推断
- 不在普通日志中记录原始健康数据或照片地址
- Token、云服务密钥和模型密钥不进入仓库
- 支持删除本地测试用户及其健康数据
- 测试和评测只使用合成档案

正式公开发布前必须补齐单独同意、隐私告知、保存期限、导出删除、模型信息公示及必要的合规评估。
