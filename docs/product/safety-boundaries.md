# 健康教练 Agent 安全边界

> 日期：2026-06-12
> 适用阶段：个人开发验证

## 1. 基本边界

产品提供健康科普、体态筛查辅助、普通健身计划、普通饮食建议和执行管理。

产品不得：

- 将自测或照片结果表述为医学确诊
- 宣称替代医生、物理治疗师、营养师或专业教练
- 承诺纠正畸形、治疗疾病或保证效果
- 仅依赖结尾免责声明放行高风险建议
- 在 AI 失败时返回“正常”或其他看似安全的假结果

## 2. 风险分级

| 等级 | 典型情况 | 产品行为 |
| --- | --- | --- |
| 普通 | 无明显限制的普通成年人 | 可在已验证的产品范围内生成完整计划 |
| 谨慎 | 新手、信息不足、既往疼痛、恢复较差 | 补充必要信息，采用保守负荷和更严格的进阶限制；缺少安全必需信息时阻止生成 |
| 受限 | 孕期、术后、重大慢性病、明显伤病、未成年人、饮食障碍风险等 | 不生成普通自动训练计划或普通自动饮食计划；仅提供健康教育、记录、体态辅助，以及对应领域规格明确允许的有限模式 |
| 红旗 | 急性创伤、明显神经或心血管等风险信号 | 停止相关计划生成、替换、调整或执行，不提供绕过停止条件的替代动作，并给出及时就诊建议 |

所有用户拥有产品访问权，但推荐强度和可执行动作根据风险等级变化。

风险规则必须由版本化代码或策略数据实现，不能只写在 Prompt 中。

专业人员建议或用户声称已获专业确认，不会自动把“受限”降为“普通”。只有当对应领域规格明确支持该有限模式，并记录建议来源、适用范围、时间和限制后，系统才可在这些边界内工作。风险等级恢复必须基于更新后的结构化档案重新分类；不得仅因时间经过或用户点击确认自动解除限制。

### 推荐请求安全门

以下操作每次执行前都必须使用最新结构化信息重新进行资格与风险分类：

- 体态改善优先级建议
- 训练计划生成和重新生成
- 动作替换、当日缩短、顺延和恢复性调整
- 长期训练结构或强度调整
- 营养目标计算、饮食建议生成和食物替换
- 周复盘产生的后续建议

新的疼痛、伤病、麻木、无力、眩晕、胸部不适、急性创伤或其他策略配置的安全信号，必须使旧的资格判断失效。红旗结果优先于用户目标、当前计划和 AI 输出，并阻止继续调用下游生成或调整 Tool。

## 3. 体态安全

- 体态结果记录为“筛查信号”或“评估结果”
- 明确展示评估方式、时间、范围和不确定性
- 自测与照片分析冲突时保留冲突状态
- 关联图谱只能用于推荐排查和解释，不得直接认定病因
- 新发严重疼痛、麻木、无力、眩晕、急性创伤等配置为停止条件
- 图示需要展示安全姿势、常见错误和停止条件

## 4. 训练安全

计划生成前必须具备：

- 用户选择的体态评估结果
- 健身目标
- 每周频率和单次时间
- 徒手或弹力带条件
- 疼痛、伤病和限制信息
- 当前风险等级

动作库必须结构化记录：

- 适用目标和体态问题
- 难度、目标肌群、动作模式
- 所需器械
- 禁忌和停止条件
- 简化、进阶和替代动作
- 训练量和进阶规则

安全规则先过滤动作和负荷，AI 只能在允许范围内组合与解释。

确定性训练引擎必须能够独立生成完整、结构化、可校验的基线计划。AI 只能在安全候选和训练量边界内进行偏好适配与解释；任何 AI 修改都必须再次通过 schema 和确定性安全校验。模型不可用时应返回基线计划或明确的不可用状态，不得生成未经校验的替代结果。

## 5. 饮食安全

- 只支持普通饮食建议
- 即使不支持特殊饮食，也必须记录并排除过敏和明确忌口
- 营养目标和份量换算由确定性计算与食物数据库完成
- AI 不得自行发明营养值、过敏信息或疾病饮食限制
- 用户界面展示估算区间，不制造无法由份量估算支持的精确数值
- 疾病治疗饮食、孕期、未成年人和饮食障碍风险进入受限策略

确定性营养计算、份量换算和排除规则必须能够在没有 AI 时独立运行。AI 只能对已校验的结构化结果做偏好适配和解释；模型不可用不得绕过过敏、忌口、风险分级或营养边界。

## 6. Agent 工具安全

每个 Tool 必须具备：

- 明确、类型化的输入输出
- 当前用户授权检查
- 最小必要数据读取
- 明确副作用
- 可重试或幂等策略
- 失败状态和审计记录

Agent 不直接执行任意 SQL，也不将自然语言直接写入正式档案或计划。

长期结构变化需要用户确认。当日小调整可以自动执行，但必须记录调整原因并向用户展示。

## 7. 数据和隐私

体态照片、身体数据、疼痛、疾病、饮食限制和健康档案按敏感数据处理。

个人开发阶段也应做到：

- 最小化采集
- 测试和评测默认只使用合成档案；在隐私门完成前，不采集其他真实用户的体态照片、疼痛、伤病或健康档案
- 首次处理任何真实敏感健康数据前，提供目的明确的告知，并在适用时取得单独、明确的同意
- 告知本地与云端处理边界、第三方或模型提供者、保存期限、删除方式，以及拒绝或撤回同意后的产品行为
- 未取得照片或云端模型处理所需同意时，不上传数据，并提供不依赖该处理的路径或明确说明功能不可用
- 区分用户陈述、测量数据、算法计算和 AI 推断
- 不在普通日志中记录原始健康数据或照片地址
- Token、云服务密钥和模型密钥不进入仓库
- 支持删除本地测试用户及其健康数据
- 对真实用户数据提供查阅、更正和删除路径；保存期限到期或处理目的完成后执行删除或不可逆匿名化

正式公开发布前还必须完成隐私告知和同意流程的法律审查、数据导出、第三方处理清单、模型信息公示及必要的合规评估。个人开发阶段的简化实现不能作为公开发布时的默认合规结论。
